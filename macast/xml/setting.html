常见问题

Macast 启动后，任务栏会有一个小图标。手机或电脑上的 DLNA 客户端（视频 App 里的「投屏」按钮）只要和这台电脑在同一个局域网，就能搜到它，选中即可推流播放。

搜不到这台电脑

  • 防火墙：放行 Macast 用的端口（当前是 29431，可在「设置」里改）。
  • 路由器：开启 UPnP，关闭 AP 隔离。
  • iOS 设备：确认 App 有「查找并连接本地网络设备」的权限。
  • 多网卡：虚拟网卡（VMware、WSL、Hyper-V）会干扰组播，建议只保留正在用的那块。
  • UDP 组播：部分 Windows + 路由器组合需要把 IGMP 版本强制为 v2。

怎么装第三方播放器插件

  1. 从 xfangfang/Macast-plugins 下载插件
  2. 右键托盘图标 → 打开配置目录
  3. 把插件 .py 放进 renderer 目录
  4. 重启 Macast，在「设置 → 选择播放器」里选中它

找不到想要的插件？可以看这里自己写一个，欢迎提交 pull request。

配置文件在哪

系统路径
Windows%HOMEPATH%\AppData\Local\xfangfang\Macast
macOS$HOME/Library/Application Support/Macast/
Linux$HOME/.config/Macast

给 mpv 加个人配置

Windows 下新建 %HOMEPATH%\AppData\Roaming\mpv\mpv.conf，把 mpv 命令行参数写进去即可，例如：

fs-screen=1

快捷键放在同目录的 input.conf 里。更多参数见mpv 手册。

启动就崩

Macast 启动时会在本机开一个 HTTP 端口（当前是 29431）。如果这个端口已经被别的程序占用，程序会直接启动失败，表现是双击后托盘图标一闪就没，或者干脆出不来。

处理办法两种任选：关掉占用该端口的程序；或者在本页「设置」标签里把 ApplicationPort 改成别的值（比如 29432），保存后 Macast 会自动重启，并从这个配置文件里读取新端口。

想看具体是哪一步失败的，用命令行启动 python Macast.py，报错会直接打在控制台上，常见的两行是 Port 29431 not free 和 ENGINE Serving on ...。

退出卡住 / 无响应

使用第三方播放器插件时，插件通常需要额外开线程或子进程（比如拉起 mpv、PotPlayer、mpv.net）。如果这些线程在退出时没有被正确回收，就会出现「点了退出但进程还在」「界面卡住没反应」的情况，原因基本都在插件本身，而不是 Macast 主程序。

遇到这种情况：先在任务管理器里结束残留的播放器进程，再结束 Macast。如果某个插件经常这样，换回自带的 MPV 渲染器对比一下，就能确认是不是它的问题。
